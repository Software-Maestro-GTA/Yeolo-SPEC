# [API-USER-4] 내 언어 설정 변경

## 1. 기본 정보

- **Method**: `POST`
- **Endpoint**: `/api/users/me/language`
- **통신 방식**: REST
- **인증 필요**: Y
- **Success Status**: `200`

## 2. Request 사양

### Header
{
"Authorization": "Bearer {accessToken}",
"Content-Type": "application/json",
"Accept-Language": "ko"
}

### Path Params
없음

### Query Params
없음

### Request Body
```json
{
"language": "ko"
}
```

## 3. Response 사양

### 성공 응답 (Status 200)
```json
{
"status": 200,
"message": "언어 설정 변경 성공",
"data": {
"language": "ko"
}
}
```

### Error Codes
400: 잘못된 JSON, language 누락, null·빈 문자열·잘못된 타입 또는 지원하지 않는 언어 코드
401: 인증 토큰 누락, 유효하지 않거나 만료된 토큰
500: 서버 오류

### 실패 응답
```json
{
"status": 400,
"message": "지원하는 언어 코드를 입력해주세요.",
"data": null
}
```

## 4. 상세 내용 및 예외 케이스

## 기능

로그인한 사용자의 선호 언어 설정을 요청한 값으로 교체하고 저장한다. 사용자 식별은 Authorization 헤더의 액세스 토큰을 기준으로 한다.


## 요청 규칙

- `language`: 필수 문자열. BCP 47 형식의 서비스 지원 언어 코드만 허용한다.
- `ko`는 한국어 요청 예시이며, 전체 지원 언어 목록은 별도 확정한다.
- 필드 누락, `null`, 빈 문자열, 잘못된 타입, 지원하지 않는 코드는 `400`으로 거절하며 기존 설정을 유지한다.

## 저장 및 응답 규칙

- 언어 설정이 없으면 생성하고, 있으면 해당 값으로 교체한다.
- 같은 값으로 반복 요청해도 저장 결과는 동일하며 `200`을 반환한다.
- `data.language`는 저장 완료된 언어 코드를 반환한다.
- 저장한 설정은 이후 내 언어 설정 조회 API에서 반환한다.

## 언어 헤더 정책 (제안)

- 요청 헤더 `Accept-Language`는 선택 사항이며, 이번 응답의 사용자 표시용 `message` 언어를 지정한다. 예: `ko`, `en`, `ko-KR,ko;q=0.9,en;q=0.8`. 예시가 전체 지원 언어 목록을 의미하지는 않는다.
- 계정에 저장할 언어는 요청 본문의 `language`로만 결정한다. 헤더와 본문이 다르면 본문 값을 저장하고, 메시지 언어는 헤더 정책을 따른다.
- 응답 언어는 헤더의 지원 언어 중 우선순위가 높은 언어 → 저장된 선호 언어 → 서비스 기본 언어 순으로 결정한다. 성공 시 저장된 선호 언어는 변경 완료된 값을 기준으로 한다. 지역 코드 매칭 및 지원 언어 목록은 별도 확정한다.
- 헤더가 없거나 매칭되는 지원 언어가 없으면 저장된 선호 언어 또는 서비스 기본 언어로 폴백한다. 헤더의 미지원 언어만으로 `400`을 반환하지 않는다. 본문 `language`의 유효성 검증은 기존 요청 규칙을 따른다.
- `data.language`는 저장한 언어 코드이며, 응답 메시지 언어와 다를 수 있다.
- 응답 헤더 `Content-Language`에는 실제 메시지에 적용한 언어 코드를 반환한다. 성공·실패 응답에 동일한 정책을 적용하며, 사용자를 식별할 수 없는 인증 실패 응답은 요청 헤더 또는 기본 언어를 사용한다.
- 현재 성공·실패 응답 속성의 한국어 문구는 `ko` 응답 예시다.

## 적용 범위

계정별 선호 언어 저장을 담당한다. 프론트엔드는 성공 응답의 언어 코드를 기준으로 UI 언어를 반영한다. 기존 콘텐츠 번역 및 AI 응답 언어 적용은 별도 정책으로 정의한다.
