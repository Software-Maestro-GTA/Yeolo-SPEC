- **통신 방식**: REST
- **인증 필요**: N
- **Success Status**: `200`

## 4. 상세 내용 및 예외 케이스

## 기능

사용자가 키워드 입력을 완료하고 검색을 실행하면 국가·도시를 검색하여 국가별 도시 이름 목록으로 묶어 반환한다. 입력 중 자동완성 호출은 하지 않는다.


## 요청 규칙

- `keyword`: 필수 문자열. 앞뒤 공백을 제거하며, 공백 제거 후 빈 문자열이면 `400`을 반환한다.
- 검색은 등록된 국가·도시 이름 및 다국어 별칭을 대상으로 하며 영문 대소문자는 구분하지 않는다.
- 중간 문자열 포함 검색이나 초성 검색이 아니라 접두어 검색을 기본으로 한다.
- `limit`, 페이지네이션 없이 아래 규칙에 매칭되는 전체 결과를 반환한다.

## 매칭 규칙

1. 키워드가 국가 이름과 완전 일치하면 해당 국가의 서비스 등록 도시 전체 목록을 반환한다. 예: `일본` → 일본의 전체 도시 목록.
1. 완전 일치 국가가 없으면 국가명과 도시명에 대해 접두어 검색을 수행한다. 예: `다` → 이름이 ‘다’로 시작하는 국가와 도시.
1. 국가명이 접두어로 매칭되면 그 국가의 전체 도시 목록을 포함한다. 도시명만 매칭되면 소속 국가 아래 매칭된 도시만 포함한다.
1. 같은 국가에 대한 결과는 하나로 묶고 중복 도시는 제거한다. 국가명 매칭으로 전체 도시가 포함된 경우 도시명 매칭 결과를 다시 추가하지 않는다.
1. 결과가 없으면 `200`과 `results: []`를 반환한다. 국가가 매칭되었지만 등록 도시가 없으면 해당 국가를 `city: []`로 반환한다.

## 응답 형식

- `data.results`: 국가별 검색 결과 배열.
- `country`: 국가 표시명 문자열.
- `city`: 해당 국가의 도시 표시명 문자열 배열. 요청한 `country: string`, `city: string[]` 형태를 유지한다.
- 국가 및 각 국가의 도시는 응답 표시명 기준 오름차순으로 정렬한다. 국가·도시 식별자 기준으로 그룹화·중복 제거한 후 표시명을 반환한다.
- 성공 응답 속성의 일본·도쿄·오사카는 구조를 설명하기 위한 일부 예시다. 실제 `일본` 검색 응답은 등록된 일본 도시 전체를 포함한다.

## 선택 연계 시 검토 사항

검색 응답은 요청한 이름 중심 구조로 작성했다. 도시 동명이인 등을 안정적으로 구분해야 한다면 `countryId`, `cityId`를 포함하는 구조로 추후 확장할 수 있다.


## 언어 정책

기존 `Accept-Language` 헤더를 유지한다. 검색 입력 언어와 응답 표시 언어는 별개이며, 등록된 다국어 이름·별칭을 검색한 뒤 응답 언어에 맞는 표시명을 반환한다. 지원 언어 중 요청 우선순위에 맞는 언어를 적용하며, 헤더가 없거나 지원 언어가 매칭되지 않으면 서비스 기본 언어를 사용한다. 지원 언어 목록 및 기본값은 별도 확정한다.
