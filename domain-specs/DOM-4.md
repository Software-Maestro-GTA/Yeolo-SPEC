# [DOM-4] 취향 분석 프로세스

## 목적

사용자가 동의한 사진의 위치·시간 메타데이터를 바탕으로 여행 취향 프로필을 생성한다.

클라이언트는 사진의 좌표와 촬영 시간을 전달하고, BE 서버는 이를 전처리한 뒤 AI 서버에 분석을 요청한다. AI 서버는 통계 요약과 LLM 분석을 거쳐 최종 `tasteProfile`을 생성한다.


## 전체 흐름

```plain text
사진 EXIF 데이터
→ BE 서버 위치·시간 전처리
→ AI 서버 메타데이터 통계 요약
→ LLM Fact Sheet 생성
→ 3개 영역 병렬 채점
→ Taste Profile 조립
→ SSE로 진행 상태 및 결과 반환
```


## 단계별 프로세스


### 1. BE 서버 전처리

BE 서버는 사진의 위도·경도와 촬영 시간을 받아 AI 분석에 사용할 수 있는 형태로 가공한다.

전처리 결과:

- 위치 정보
  - 국가
  - 도시
  - 지역
  - 행정구역
  - 장소명
  - 장소 유형
- 시간 정보
  - 촬영 시각
  - 요일
  - 주말 여부
  - 시간대
  - 계절

### 2. AI 서버 1차 통계 요약

AI 서버는 전달받은 사진 메타데이터를 바로 LLM에 넣지 않고, 먼저 파이썬 로직으로 정량 요약한다.

요약 항목:

- 분석된 총 사진 수
- 평일/주말 활동 비율
- 요일별 분포
- 시간대별 분포
- 계절별 분포
- 주요 방문 도시
- 자주 방문한 장소명
- 자주 등장한 장소 유형
이 단계는 LLM 입력 토큰을 줄이고, 분석 근거를 명확히 하기 위한 과정이다.


### 3. LLM Fact Sheet 생성

1차 통계 요약 결과를 바탕으로 LLM이 사용자의 여행 패턴을 정성적으로 요약한다.

Fact Sheet에는 다음 내용이 포함된다.

- 선호하는 여행 시기
- 자주 방문하는 장소 유형
- 활동 패턴
- 여행 속도감
- 음식·카페·자연·도시 선호 경향

### 4. 3개 영역 병렬 분석

Fact Sheet를 기반으로 3개의 LLM 체인이 병렬로 실행된다.

| 분석 영역 | 도출 정보 |
| :--- | :--- |
| 목적·밀도·동행 | 여행 목적, 일정 밀도, 동행 형태 |
| 장소·환경 | 선호 장소 유형, 계절·환경 선호 |
| 활동·소비·음식 | 활동 취향, 소비 성향, 음식 취향 |

각 체인은 정해진 스키마에 맞춰 점수와 enum 값을 생성한다.


### 5. Taste Profile 조립

병렬 분석 결과를 하나로 합쳐 최종 취향 프로필을 만든다.

생성되는 주요 정보:

- `travelPurpose`
- `travelPaceDensity`
- `preferredLocationType`
- `activityPreference`
- `spendingTendency`
- `companionType`
- `foodPreference`
- `seasonalEnvironmentPreference`
